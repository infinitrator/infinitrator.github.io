    Лабораторная работа №4

    Классификация с применением Scikit-Learn

    Цель работы

    Заполнить исходный ноутбук по предсказанию кредитного дефолта, обучить базовые модели классификации, сравнить их с дополнительными алгоритмами и выбрать более точную модель.

    Ноутбук

    Открыть выполненную лабораторную в Google Colab

    Посмотреть файл .ipynb в репозитории

    Ноутбук сохранён вместе с результатами выполнения всех ячеек. В нём заполнены все 26 пропусков исходного задания и добавлена самостоятельная часть.

    Данные

    Использован датасет соревнования Kaggle Give Me Some Credit. Задача состоит в том, чтобы по десяти числовым характеристикам клиента предсказать наличие серьёзной просрочки по кредиту.

    В обучающей выборке находится 50 000 записей, в тестовой — 37 500. Целевой класс несбалансирован: дефолт встречается примерно в 6% наблюдений.

    Подготовка данных

    В ходе предобработки были выполнены следующие действия:

    1. Проверены типы столбцов и пропущенные значения.
    2. Средние значения рассчитаны только по обучающей выборке.
    3. Пропуски в обучающей и тестовой выборках заполнены статистиками обучения.
    4. Целевая переменная SeriousDlqin2yrs отделена от признаков.
    5. Для моделей, чувствительных к масштабу, применён StandardScaler.

    Расчёт статистик только по обучающим данным нужен, чтобы информация из тестовой выборки не попадала в процесс обучения.

    Базовые модели

    В основной части ноутбука обучены:

    • логистическая регрессия;
    • случайный лес;
    • константный классификатор для сравнения.

    Для моделей рассчитаны accuracy, confusion matrix, ROC-кривая и ROC-AUC. Также проверено влияние порогов 0.3, 0.5 и 0.7 на количество ложноположительных и ложноотрицательных решений.

    Из-за дисбаланса классов основной метрикой выбрана ROC-AUC, а дополнительной — Average Precision. Одна accuracy может создавать ложное впечатление высокого качества: модель, почти всегда предсказывающая отсутствие дефолта, уже получает точность около 94%.

    Самостоятельное исследование

    Дополнительно были проверены kNN, SVM с RBF-ядром и гистограммный градиентный бустинг.

    Модель ROC-AUC Average Precision Accuracy
    HistGradientBoosting 0.8652 0.3955 0.8022
    RandomForest 0.8443 0.3574 0.9347
    SVM (RBF) 0.8194 0.3448 0.8402
    LogisticRegression 0.7782 0.2866 0.7442
    kNN 0.7415 0.2350 0.9316

    Лучшей моделью оказался HistGradientBoostingClassifier. Он уменьшил ошибку ранжирования по сравнению со случайным лесом: ROC-AUC вырос с 0.8443 до 0.8652.

    Значение ROC-AUC 0.9 получить не удалось. При честной проверке на фиксированной тестовой выборке доступных признаков недостаточно для такого разделения классов. Результат выше 0.9 потребовал бы новых информативных признаков, более сложного ансамбля либо мог бы появиться из-за утечки данных. Поэтому в качестве результата зафиксировано реальное улучшение, а не искусственно подобранная цифра.

    Современные алгоритмы классификации

    По публикациям для табличных данных особенно важны следующие направления:

    • XGBoost — масштабируемый регуляризованный градиентный бустинг;
    • LightGBM — быстрый histogram-based GBDT;
    • FT-Transformer — применение Transformer к табличным признакам;
    • TabPFN — предобученная модель для классификации небольших табличных наборов.

    Исследования показывают, что универсально лучшего алгоритма нет. Для обычных табличных данных градиентный бустинг остаётся сильной и практичной базовой моделью, поэтому он выбран и в самостоятельной части.

    Интеграция с веб-сервисом

    Для интеграции модели с FastAPI необходимо:

    1. Объединить предобработку и классификатор в Pipeline.
    2. Сохранить обученную модель через joblib.
    3. Создать Pydantic-схему входных данных.
    4. Загружать модель один раз при запуске приложения.
    5. Реализовать endpoint POST /predict.
    6. Возвращать вероятность дефолта и решение по выбранному порогу.
    7. Добавить валидацию, логирование, тесты и контроль версий модели.
    8. Упаковать сервис в Docker и развернуть через Uvicorn или Gunicorn.

    Порог классификации следует выбирать с учётом стоимости ошибок: для банка ложное одобрение кредита и ложный отказ клиенту имеют разную цену.

    Вывод

    В работе заполнены все задания исходного ноутбука, исследованы базовые и дополнительные классификаторы, построены ROC-кривые и проанализировано влияние порога. Гистограммный градиентный бустинг показал лучшее качество. Также были изучены современные методы классификации табличных данных и составлен план интеграции модели с веб-сервисом.
