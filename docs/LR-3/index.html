    Лабораторная работа №3

    CI/CD для статического сайта на GitHub Pages

    Цель работы

    Настроить автоматическую сборку и публикацию сайта на MkDocs после каждого изменения основной ветки репозитория.

    Изменение первоначального плана

    По исходному заданию сайт требовалось развернуть одновременно на SourceCraft и GitHub Pages. На момент выполнения работы SourceCraft оказался неработоспособен: стабильно создать и использовать репозиторий и запустить CI/CD не удалось.

    Чтобы не возвращаться к ручной сборке сайта, работа была продолжена на GitHub. Автоматическое развертывание реализовано через GitHub Actions. Таким образом, основная идея лабораторной — сборка и публикация сайта средствами CI/CD — была сохранена, но фактически работающая версия размещена только на GitHub Pages.

    Структура репозитория

    В проекте используется один удалённый репозиторий:

    • origin — публичный репозиторий на GitHub.

    Основные файлы проекта:

    .
├── .github/
│   └── workflows/
│       └── deploy-pages.yml
├── requirements.txt
└── source/
    ├── mkdocs.yml
    └── docs/
        └── LR-3/
            └── index.md

    Markdown-исходники сайта находятся в source/docs, а конфигурация MkDocs — в source/mkdocs.yml. Зависимости для сборки перечислены в requirements.txt.

    Настройка GitHub Actions

    Автоматизация описана в файле .github/workflows/deploy-pages.yml. Workflow запускается после каждого push в ветку main, а также может быть запущен вручную через интерфейс GitHub.

    В процессе развертывания выполняются следующие действия:

    1. Репозиторий загружается на runner с помощью actions/checkout.
    2. Устанавливается Python 3.12.
    3. Устанавливаются зависимости из requirements.txt.
    4. Выполняется строгая сборка сайта командой mkdocs build --strict.
    5. Каталог со статическими файлами загружается как артефакт GitHub Pages.
    6. Артефакт публикуется с помощью actions/deploy-pages.

    Workflow использует необходимые разрешения:

    permissions:
  contents: read
  pages: write
  id-token: write

    Настройки репозитория GitHub

    Для публикации сайта были выполнены следующие настройки:

    1. Репозиторий сделан публичным.
    2. В разделе Settings → Pages выбран источник GitHub Actions.
    3. Для развертывания используется окружение github-pages.
    4. Workflow получает право читать репозиторий и публиковать GitHub Pages.

    Секреты и отдельные токены для этого сценария не требуются: GitHub выдаёт workflow временный токен с разрешениями, указанными в YAML-файле.

    Порядок развертывания

    После изменения Markdown-файлов выполняются обычные команды Git:

    git add .
git commit -m "update portfolio"
git push origin main

    После push GitHub Actions самостоятельно устанавливает зависимости, собирает MkDocs и публикует новую версию. Каталог с готовым сайтом не требуется собирать и отправлять вручную.

    Проверка результата

    Первый запуск нового workflow завершился со статусом Success: этапы build и deploy были выполнены без ошибок, а результат сборки был загружен как артефакт github-pages.

    После каждого следующего push проверка выполняется в разделе Actions на странице репозитория. После успешного завершения workflow опубликованный сайт и отчёт должны открываться по HTTPS.

    Вывод

    В ходе работы был настроен автоматический CI/CD для сайта на MkDocs. Теперь каждый push в ветку main запускает сборку и публикацию сайта на GitHub Pages. Несмотря на отказ от первоначально запланированной второй платформы из-за её неработоспособности, сайт разворачивается автоматически и не требует ручного обновления собранных HTML-файлов.
